# 模板与检查表

## 1. 变更立项模板

```markdown
# <变更名>
状态：draft | approved | in_progress | validated | released
Owner：
目标日期：

## 问题与证据
## 用户与场景
## 目标 / 非目标
## 功能与非功能需求
## 验收标准
## 成功指标与当前基线
## 依赖、风险与假设
## 发布、观察和退出策略
```

## 2. ADR 模板

```markdown
# ADR-xxx：<决策>
日期：  状态：proposed | accepted | superseded
决策人：

## 背景与约束
## 决策
## 备选方案
## 正面与负面后果
## 安全、数据、成本和运维影响
## 复审触发条件
```

## 3. Pull Request 检查表

- [ ] 关联需求/OpenSpec 和验收标准。
- [ ] 说明用户可见行为与非目标。
- [ ] 单元、集成、契约/端到端测试已按风险补充并通过。
- [ ] 模型/提示词变更有固定评测集对比。
- [ ] API/schema 向后兼容或有弃用计划。
- [ ] ORM 变更有迁移，升级、兼容和恢复已验证。
- [ ] 权限、隐私、prompt injection、Artifact/sandbox 风险已评估。
- [ ] timeout、重试、幂等、预算和失败终态明确。
- [ ] 日志、指标、trace、告警和审计足以定位问题。
- [ ] 配置有安全默认值且不包含密钥。
- [ ] 用户、开发和运行文档已同步。
- [ ] feature flag、发布、回滚和清理计划明确。

## 4. 测试报告模板

```markdown
# <版本/变更> 测试报告
环境与 commit：
测试数据/模型/配置版本：

## 范围与不包含项
## 需求-测试追踪
## 自动化结果
## 手工/探索/安全/性能/模型评测结果
## 缺陷与残余风险
## 结论：通过 | 有条件通过 | 不通过
批准人和日期：
```

## 5. 发布检查表

- [ ] 发布范围、commit、构建产物和 SBOM 已冻结。
- [ ] 配置差异、密钥和外部配额已确认。
- [ ] 备份恢复、数据库 migration 和兼容路径已验证。
- [ ] smoke test、灰度组、指标和停止阈值已准备。
- [ ] feature flag/capability gate 可即时关闭。
- [ ] 应用、配置和数据回滚分别可执行。
- [ ] 值守、Incident Commander 和沟通渠道已确认。
- [ ] 发布说明包含已知限制和迁移提示。
- [ ] 技术与产品观察窗口有 owner。

## 6. 生产事件模板

```markdown
# INC-xxx：<标题>
严重度：  状态：  Incident Commander：
开始/发现/恢复/结束时间：

## 用户影响和范围
## 当前缓解
## 时间线（时间、事实、决定、行动、结果、负责人）
## 根因与促成因素
## 检测和响应评价
## 防复发任务（优先级、owner、期限、验证）
## 用户/监管沟通
```

## 7. Definition of Ready

- [ ] 问题、用户、价值和范围明确。
- [ ] 验收标准可测试，关键非功能需求已量化。
- [ ] 依赖、数据、安全和主要风险已识别。
- [ ] OpenSpec/设计深度与变更风险匹配。
- [ ] 团队可在一个可控增量内交付和演示。

## 8. Definition of Done

- [ ] 实现、评审、自动化检查与验收完成。
- [ ] 迁移、兼容、可观测性、安全和隐私要求完成。
- [ ] 发布和回滚已验证，残余风险有批准和期限。
- [ ] 文档、版本说明和 Runbook 同步。
- [ ] 生产观察指标、窗口和 owner 明确。

## 9. 文档审查清单

- [ ] 区分现状、目标、假设和决策。
- [ ] 命令、路径、接口和配置与当前仓库一致。
- [ ] 链接有效，术语一致，正文中文且协议标识精确。
- [ ] 无密钥、个人数据、内部地址或不必要敏感细节。
- [ ] 指明 owner、更新时间、适用版本和复审条件。
