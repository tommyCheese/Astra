# 安全、隐私与合规

## 1. 全生命周期安全

安全不是发布前一次检查。发现阶段识别滥用与敏感数据；需求阶段定义权限和保留；设计阶段威胁建模；开发阶段安全编码与扫描；测试阶段对抗验证；发布阶段最小权限和密钥轮换；运营阶段检测、响应和审计；退役阶段撤权和数据处置。

## 2. 数据分类与隐私

建议分类：Public、Internal、Confidential、Restricted。用户输入、抓取正文、Memory、ToolCall 参数、Artifact、日志和模型 provider 请求分别标注分类、处理目的、法律依据（适用时）、存储位置、访问者、保留期和删除机制。

遵循数据最小化：只收集完成任务所需内容；发送到第三方模型/工具前明确边界；敏感字段脱敏或不记录；用户删除应覆盖主数据、索引、Artifact 和依法可删除的备份周期。生产数据不得直接进入开发测试。

## 3. 身份、授权与批准

认证确认主体，授权检查主体能否对具体 Task/Run/Artifact 执行动作。所有查询按 tenant/workspace/user 范围过滤，不能仅凭 UUID 难猜测。Artifact content endpoint 必须校验访问权和 `security_status`，不能只检查文件存在。

权限采用最小化、短期凭据和职责分离。外部写入、发消息、付款、删除、发布等副作用按风险请求显式批准；批准记录绑定规范化参数、过期时间和 Run，参数变化后重新批准。

## 4. Agent 威胁模型

重点威胁：prompt injection、工具混淆、跨租户数据、越权调用、敏感信息外发、Memory poisoning、模型错误完成、资源耗尽、供应链攻击、沙盒逃逸和主动 Artifact。

控制基线：外部内容标记为不可信数据；system/policy 不与工具数据混淆；模型只看到策略允许的 manifest；Router 确定性执法；输出 schema 校验；预算和速率限制；来源/provenance；完成门禁；危险操作批准；隔离计算；Artifact 内容验证与隔离展示。

## 5. 应用与基础设施安全

- 密钥进入专用 secret manager，禁止源代码、日志、Artifact 和前端 bundle。
- 依赖锁定并生成 SBOM，执行 SCA、许可证和镜像扫描。
- 容器非 root、只读根文件系统、最小 capability、网络默认关闭、资源限制。
- 数据传输 TLS，静态数据按风险加密，密钥可轮换。
- CORS、CSP、cookie、CSRF 和下载 header 使用生产安全配置。
- 审计日志防篡改、限制访问并有保留策略。

## 6. 安全验证与漏洞响应

合入前运行静态/依赖/secret 扫描；高风险能力做人工威胁评审和对抗测试。至少测试 IDOR、路径逃逸、SSRF、prompt injection、恶意 SVG/HTML、压缩炸弹、超大输出、命令注入、sandbox escape 假设、日志注入和错误信息泄露。

漏洞接收后确认影响与可利用性，先缓解再修复，必要时轮换密钥和通知。修复带回归测试；披露和通知遵循适用合同与法规。风险接受必须有业务 owner、理由、补偿措施和到期日。

## 7. 合规证据

保留需求批准、设计评审、访问审计、测试报告、发布记录、变更审批、事件复盘、恢复演练、供应链清单和数据处置证明。合规要求应转换成自动化控制和可重复证据，不依赖临时截图或个人记忆。
