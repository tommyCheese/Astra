## ADDED Requirements

### Requirement: 可信运行以规范计划图为主要过程视图
系统 SHALL 为存在规范 Plan 的 trusted Run 展示可交互的分层 DAG，并 SHALL 使用同一图谱组件覆盖等待确认、执行中、等待用户、失败、重规划和完成状态。

#### Scenario: 完整计划等待确认
- **WHEN** trusted Run 已生成完整 Plan 并等待用户确认
- **THEN** UI 在确认操作之前展示该版本的全部节点和依赖边
- **THEN** UI 不再用线性有序列表替代 DAG 结构

#### Scenario: 计划正在执行
- **WHEN** trusted Run 的 Plan 已激活
- **THEN** 图谱实时突出当前节点、已完成路径、可执行节点和未满足依赖的节点
- **THEN** 图谱显示完成节点数、总节点数和当前计划版本

#### Scenario: 可信运行完成后重新打开
- **WHEN** 用户从历史会话打开已完成的 trusted Run
- **THEN** UI 从持久化图谱快照恢复相同节点、依赖、版本和终态

### Requirement: 图谱使用确定性且语义稳定的布局
系统 SHALL 根据依赖层级生成稳定的有向布局，并 MUST NOT 将节点的自由拖动位置解释为执行顺序或计划修改。

#### Scenario: 相同计划再次渲染
- **WHEN** 相同 Plan 版本在刷新、历史重载或窗格尺寸切换后重新布局
- **THEN** 节点保持相同的层级顺序和可预测位置
- **THEN** 依赖箭头始终从前置节点指向后继节点

#### Scenario: 计划包含并行和汇合
- **WHEN** 多个节点共享同一前置节点或汇合到同一后继节点
- **THEN** 图谱显示清晰的 fan-out 和 fan-in 结构
- **THEN** UI 不按节点 index 将并行分支误画成串行链

### Requirement: 节点状态和依赖传播可以一眼识别
系统 SHALL 对 pending、ready、running、completed、failed、blocked、skipped 和 superseded 使用兼容文字、图标及颜色的状态表达，并 SHALL 突出失败或阻塞所影响的依赖关系。

#### Scenario: 前置节点失败
- **WHEN** 某节点因必要前置节点失败而无法执行
- **THEN** 受影响节点显示 blocked 状态
- **THEN** 导致阻塞的依赖路径可从图谱中识别

#### Scenario: 用户使用非彩色或减弱动画环境
- **WHEN** 颜色不可辨识或系统启用 reduced-motion
- **THEN** 状态仍可通过文字、图标、边框和线型识别
- **THEN** 当前节点不依赖持续动画表达

### Requirement: 节点检查器展示计划、执行和证据详情
系统 SHALL 在用户选择节点时展示该节点的计划意图、依赖、预期结果、成功准则、能力、风险、可选性、实际执行、工具、产物、证据、失败信息和版本来源。

#### Scenario: 查看已完成节点
- **WHEN** 用户选择一个 completed 节点
- **THEN** 检查器展示完成证据和关联工具及产物
- **THEN** 用户可以从节点跳转到对应可见产物或安全审计记录

#### Scenario: 查看等待节点
- **WHEN** 用户选择一个 pending 或 blocked 节点
- **THEN** 检查器说明尚未满足的依赖或阻塞原因
- **THEN** UI 不把未执行节点呈现为已验证成果

### Requirement: 计划图与实际运行记录分层展示
系统 SHALL 将 Plan DAG 表示为“应该执行什么”，并 SHALL 将 AgentTurn、ToolCall、Reflection、Verification 和 Artifact 表示为选定节点内或次级的实际运行 Trace。

#### Scenario: 一个计划节点发生多轮尝试
- **WHEN** 一个节点经历多个推理轮次、工具调用或反思
- **THEN** 主图仍保留一个规范计划节点
- **THEN** 节点检查器按实际发生顺序展示其运行 Trace

#### Scenario: 用户查看完整时间顺序
- **WHEN** 用户展开运行记录
- **THEN** UI 继续提供跨节点的线性审计时间线
- **THEN** 线性时间线不取代规范 DAG 的依赖表达

### Requirement: 用户可以请求生成新的计划版本
系统 SHALL 在 trusted Run 等待计划确认时允许用户用自然语言提出修订，并 SHALL 在后台生成、校验和持久化新的完整 DAG 后重新请求版本绑定确认。

#### Scenario: 修订请求有效
- **WHEN** 用户针对当前等待确认的 Plan 提交修订意图
- **THEN** 系统创建经过完整 DAG 校验的新计划版本
- **THEN** UI 展示新版本和相对上一版本的结构差异
- **THEN** 任何节点均不会在新版本确认前执行

#### Scenario: 修订请求产生非法计划
- **WHEN** 修订结果包含环、未知依赖、无根节点、不可达节点、能力越界或预算越界
- **THEN** 系统拒绝该修订版本
- **THEN** 原计划继续保持等待确认且没有节点开始执行

#### Scenario: 用户尝试直接改写图结构
- **WHEN** 用户拖动节点或操作图谱视口
- **THEN** UI 只改变本地查看状态
- **THEN** 系统不据此创建、删除或重连规范计划节点

### Requirement: 计划版本差异和成果沿袭可审计
系统 SHALL 展示当前版本与其前一版本之间新增、删除、修改、保留和继承完成状态的节点及依赖变化。

#### Scenario: 重规划替换未完成分支
- **WHEN** trusted Run 从 v1 重规划为 v2
- **THEN** UI 明确显示 v2 替代 v1
- **THEN** 未受影响且被沿袭的完成节点及证据显示为保留
- **THEN** 新增、删除和依赖变化可以分别识别

#### Scenario: 用户查看旧版本
- **WHEN** 用户从版本选择器查看 superseded Plan
- **THEN** UI 将该版本标记为历史版本且不显示为当前可执行计划
- **THEN** 当前运行状态不会被旧版本视图覆盖

### Requirement: 图谱在不同设备和辅助技术中保持可用
系统 SHALL 提供聊天右侧概览、半屏工作台、平移缩放、定位中心和图谱原生键盘节点导航，并 SHALL 在大图时保持可读和可恢复导航。系统 MUST NOT 通过重复的线性结构化节点列表或缩略图取代或附加于可交互图谱。

#### Scenario: 紧凑聊天宽度
- **WHEN** 图谱显示在普通聊天消息宽度中
- **THEN** UI 提供可扫描概览和容器级“扩大图谱窗格”操作
- **THEN** 节点文字、确认操作和运行状态不相互遮挡

#### Scenario: 键盘或屏幕阅读器用户浏览图谱
- **WHEN** 用户不使用指针设备或使用屏幕阅读器
- **THEN** 用户可以按依赖层级导航节点并打开检查器
- **THEN** 图谱节点自身提供标题、状态、依赖和版本上下文
- **THEN** UI 不额外显示重复的结构化节点列表

#### Scenario: 计划节点数量超出紧凑视图容量
- **WHEN** Plan 较大而无法在聊天区域同时清晰展示全部节点
- **THEN** UI 自动定位完整图谱并允许扩大到半屏工作台
- **THEN** 图谱不会通过截断节点或依赖来伪造更简单的计划

### Requirement: 图谱独立于思考记录持续可见
系统 SHALL 将 trusted Run 的当前 Plan 图谱展示为对话级独立窗格，SHALL 默认将其放置在对话输出右侧，并 MUST NOT 依赖“思考/过程”折叠区的展开状态才能观察图谱。

#### Scenario: 用户收起思考记录
- **WHEN** trusted Run 已存在规范 Plan 且用户收起或尚未展开过程记录
- **THEN** 当前图谱仍在对话输出右侧的独立悬浮窗格中可见
- **THEN** Plan 确认、调整和取消操作仍位于原确认流程中

#### Scenario: 用户调整图谱视口
- **WHEN** 用户点击图谱窗格的放大、缩小或定位中心按钮
- **THEN** 图谱视口立即响应并保持计划数据不变
- **THEN** 定位中心将 DAG 的几何中心移动到画布中心且不改变当前缩放比例
- **THEN** 视口操作不会确认计划、执行节点或修改依赖

#### Scenario: 用户扩大右侧图谱窗格
- **WHEN** 宽屏用户点击“扩大图谱窗格”
- **THEN** 对话区和图谱窗格各占可用内容区约一半
- **THEN** 图谱显示扩大的完整画布并重新定位完整图谱
- **THEN** 图谱不显示缩略图或重复的图内全屏入口
- **THEN** 用户可以恢复默认窗格宽度而不改变计划或节点选择

#### Scenario: 可用宽度不足
- **WHEN** 视口无法同时容纳对话和右侧图谱列
- **THEN** 图谱降级为可收起的悬浮覆盖窗格
- **THEN** 用户可以恢复图谱且不丢失当前运行状态

#### Scenario: 同一会话产生新的图谱
- **WHEN** 后续 trusted Run 产生新的规范 Plan 图谱
- **THEN** 右侧悬浮窗格原位刷新为最新 Run 的图谱
- **THEN** 旧 Run 的图谱以默认收起的小图标入口保留在对应对话过程条目中
- **THEN** 用户可以独立展开和收起旧图谱，且旧图谱内容不随最新 Run 更新

### Requirement: 图谱视觉层级现代且保持主题一致
系统 SHALL 使用 Astra 现有主题色和状态语义渲染分层毛玻璃工作台、节点卡片及依赖边，并 SHALL 在视觉增强后继续保持文本、方向和状态可辨识。

#### Scenario: 用户浏览复杂多路图谱
- **WHEN** 图谱包含多个并行分支和汇合节点
- **THEN** 画布、节点和连线通过空间层级、柔和光影与清晰箭头形成可扫描的结构
- **THEN** 状态仍通过文字、图标、边框或线型表达，而不只依赖发光颜色

#### Scenario: 用户使用暗色、高对比或减弱动画主题
- **WHEN** 当前主题为暗色、forced-colors 或 reduced-motion
- **THEN** 图谱沿用对应主题令牌并保持足够对比度
- **THEN** 装饰性模糊和动画不会妨碍阅读或成为状态信息的唯一来源
