## Why

可信执行已经在后台生成、持久化并按版本执行真实 Plan DAG，但前台仍将计划节点、依赖和运行过程投影为线性列表，用户无法直观看到并行分支、依赖汇合、当前执行路径、阻塞传播或重规划变化。随着 Agent 产品从聊天记录走向可持久化、可干预、可审计的图工作流，Astra 需要让规范计划成为可信模式的主要交互对象，而不再把它隐藏在“思考过程”内部。

## Current Implementation Baseline (2026-08-12)

- 版本化图谱投影、Plan 修订、SSE reducer、确定性 Dagre 布局、节点检查器、版本差异、对话级右侧窗格、半屏模式、历史 Run 入口以及无障碍/主题处理均已落地。
- 全屏与 minimap 路径已经按现行设计移除；半屏窗格是本变更确定的扩展语义，不再保留为待决项。
- OpenSpec 任务仅剩真实浏览器验收，且应与并行 DAG 的多 running/resource wait/fan-in 场景共享验收记录。
- replay/fork、层级子图、多 Agent ownership、跨 Run 对比与关键路径预测继续作为未来独立提案，不纳入当前收尾。

## What Changes

- 为 trusted Run 增加“可信执行图谱工作台”，以确定性分层 DAG 展示计划节点、依赖边、执行状态、当前路径和总体进度。
- 统一等待计划确认、执行中、等待审批、失败、重规划和完成后的图谱表现；计划确认不再使用独立的线性节点列表。
- 提供节点检查器，展示意图、依赖、预期结果、成功准则、能力、风险、工具调用、产物、证据和失败原因。
- 将规范 Plan DAG 与实际运行记录分层：图谱回答“应该执行什么”，节点内 Trace 回答“实际发生了什么”；现有线性推理、工具、反思和验证过程保留为次级审计视图。
- 将图谱从“思考/过程”折叠区移到对话输出右侧的独立悬浮窗格，使用户在阅读回答或收起过程记录时仍能持续观察计划；图内提供显式放大、缩小和定位中心操作。
- 为右侧窗格增加半屏扩展状态，使图谱与对话在宽屏上各占一半，并与图内视口操作保持不同语义。
- 对 standard Run 保持现有轻量线性过程，不创建或展示 DAG 占位。
- 增加面向图谱的版本化投影和增量事件，使节点状态、计划激活和重规划可实时更新，并能通过完整快照恢复。
- 展示当前计划版本、版本沿袭和结构差异；已完成且被新版继承的节点和证据保持可见。
- 在等待计划确认时允许用户用自然语言请求修订，后台生成并校验新的完整 DAG 版本后重新展示；不提供自由拖拽、任意连线或绕过计划校验的直接编辑。
- 增加适配紧凑聊天宽度、半屏查看、缩放导航、图谱原生键盘与屏幕阅读器操作、暗色模式和 reduced-motion 的响应式交互，不重复提供线性节点列表或缩略图。
- 在不改变 Astra 现有主题色和状态语义的前提下，以分层毛玻璃、柔和空间光、现代节点卡片和精细依赖连线重绘图谱，使复杂 DAG 更易扫描且保持克制。

## Capabilities

### New Capabilities

- `trusted-execution-graph-workbench`: 定义 trusted Plan DAG 的图谱展示、生命周期状态、节点检查、计划确认、自然语言修订、版本差异、响应式布局和无障碍行为。
- `trusted-plan-graph-projection`: 定义规范 Plan、版本沿袭、节点执行关联、图谱快照与增量事件的前端投影合同和恢复语义。

### Modified Capabilities

- `agent-chat-ui`: 将 trusted Run 的规范计划改为主要过程视图，将线性运行过程降为节点内或次级审计记录，同时保持 standard Run 的轻量线性体验。
- `task-runner`: 向客户端提供完整、版本化且可恢复的 Plan 图谱、节点状态、沿袭、执行关联和计划修订结果。
- `general-agent-reasoning`: 允许等待确认的 trusted Run 接收用户修订意图，并仅通过后台验证后创建新的完整 DAG 版本。
- `low-latency-answer-streaming`: 对高频图谱节点和版本变化使用有界增量投影，避免每个节点事件触发完整 RunView 刷新。

## Impact

- 前端：聊天过程信息架构、计划确认卡、审计视图、Run 状态管理、SSE reducer、图布局与交互组件、国际化及可访问性测试。
- 后端：RunView Plan 投影、Plan 版本查询、节点 lineage/执行关联、用户修订续跑协议、图谱 snapshot/delta 事件和安全清洗。
- 数据与协议：复用现有 Plan、PlanNode、PlanEdge、AgentTurn、ToolCall、Artifact 和 RunEvent；可能扩展公开字段及索引，但不以 UI 布局坐标污染规范计划。
- 依赖：需要评估并锁定支持确定性分层布局、缩放和无障碍集成的前端图形方案；不得让布局库成为执行语义来源。
- 非目标：本变更不引入通用低代码工作流编辑器、循环 Plan、跨 Run 记忆图、多 Agent 网络编辑、任意拖拽改写计划或隐藏思维链展示。
