## Why

Astra 当前的 Agent loop 已能围绕 Web 工具做结构化决策并记录反思，但计划、观察、反思和最终完成之间缺少可执行的正确性契约：反思结果不会强制改变后续状态，阻塞或验证失败后仍可能进入最终生成，用户在界面选择的推理强度、规划策略和反思策略也尚未进入后端运行策略。现在需要把这些能力抽象为与具体工具无关的通用推理内核，作为后续代码、文件、浏览器和外部系统任务的共同控制层。

## What Changes

- 引入任务契约，将用户目标转换为约束、成功标准、禁止事项、风险与验证要求，并在执行期间持续跟踪满足状态。
- 引入通用 Agent 状态和可修订计划图，使每轮决策关联目标步骤、预期观察、成功标准、风险、置信度和失败回退策略。
- 引入策略编译，将推理强度、规划策略、反思开关与触发方式、执行批准模式和验证强度编译为不可变、可审计的 Run 策略快照。
- 将反思分为局部修正、计划重构和目标级升级，并要求有效反思产生工具输入、计划、事实状态或运行状态的明确变化。
- 引入事件驱动的反思门控、无进展检测、失败策略去重和有界重试，避免无效或无限反思。
- 引入独立完成闸门；只有任务契约、必要验证和安全约束满足时才能完成，否则进入等待用户、阻塞、失败或带警告完成。
- 保留隐藏思维链不持久化的边界，只保存面向用户和审计的结构化推理摘要、诊断和状态变化。
- 将现有 Web Agent 作为首个适配对象，同时解除推理、反思和验证协议对 Web 来源结构的硬编码依赖。

## Capabilities

### New Capabilities

- `reasoning-policy`: 定义用户推理、规划、反思、批准与验证偏好如何编译为受安全下限约束的有效运行策略。
- `general-agent-reasoning`: 定义任务契约、计划图、结构化逐轮决策、观察评估和通用 Agent 状态推进。
- `structured-reflection`: 定义反思触发、诊断层级、状态修订、重试预算、无进展检测和反思审计。
- `completion-gate`: 定义与任务类型适配的验证协议、严格终态语义，以及完成、等待用户、阻塞和带警告完成的判定。

## Impact

- 后端 Agent runtime 将新增策略编译器、任务契约、计划状态、评估/反思门控和完成闸门，并调整 `RunEngine`、`AgentLoop`、模型客户端与验证器的职责边界。
- Agent decision、reflection、run policy、turn 和 API view schema 将扩展；数据库可能需要持久化任务契约、策略快照、计划版本、标准状态和终态原因。
- 前端现有的推理强度、规划策略、反思设置与执行模式将接入 Run 创建请求，并展示请求策略、有效策略和自动调整原因。
- 现有 Web 工具、Evidence Pack、Memory 和审计记录继续保留，但通过通用协议适配；测试需要覆盖策略组合、反思修订、终态隔离和恢复兼容。
- 不引入新的外部依赖或新工具权限；本 change 聚焦 Agent 控制内核。
