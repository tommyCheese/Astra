## Why

Astra 当前只展示自身生成的公开运行摘要，即使用户显式开启了模型思考，供应商返回的可见思考正文也会在传输层丢失。用户需要在明确开启模型思考时查看供应商实际公开返回的完整思考内容，同时仍能区分它与 Astra 的计划、工具和审计摘要。

## What Changes

- 采集兼容供应商在流式与非流式响应中显式返回的模型思考正文，并保持原始顺序与换行。
- 仅当 Run 的生效模型思考配置为开启时，发布并持久化独立的模型思考内容；关闭或不支持时不产生该内容。
- 在 Astra 过程面板中将“模型思考”作为独立、可展开的流式条目完整展示，不与 `reasoning_summary` 混合。
- 对只返回 reasoning token 数或不公开正文的供应商显示明确的不可用状态，不推断或伪造思考内容。
- 保持凭据、请求提示、工具敏感输入和供应商未公开的隐藏思维链不可见。

## Capabilities

### New Capabilities

- `model-thinking-content-stream`: 定义供应商公开思考正文的采集、流式事件、持久化、恢复和可用性语义。

### Modified Capabilities

- `agent-chat-ui`: 在过程面板中独立、完整地展示已公开的模型思考正文。
- `runtime-reasoning-policy-enforcement`: 将“禁止转发任何思考正文”调整为只允许转发供应商明确公开且用户已开启的思考正文，同时继续隔离未公开思维链。
- `provider-reasoning-adaptation`: 记录供应商是否公开思考正文，并从兼容响应字段提取内容而不泄露其他响应元数据。
- `model-thinking-controls`: 将思考正文的显示与有效模型思考开关绑定，并允许审计存储用户请求展示的公开正文。

## Impact

- 后端模型传输、流式 JSON 解析、Agent 事件协议、Run 快照和对话投影。
- 前端过程流 reducer、过程面板、类型、文案与样式。
- Provider 兼容矩阵与模型调用测试、事件恢复测试和前端渲染测试。
- Run 数据量会增加；内容必须设置单次调用和单 Run 上限，并在达到上限时显式标记截断。
