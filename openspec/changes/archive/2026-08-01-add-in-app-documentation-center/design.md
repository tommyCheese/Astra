## Context

Astra 目前通过 `App.tsx` 中的顶层 `view` 状态在聊天、设置、资料库、Skills 和分享管理之间切换。侧边栏是这些工作区的稳定入口，但没有帮助入口；记忆说明也只能从设置标签和实现代码中拼凑。新文档中心需要融入现有应用壳、保持纯前端可用，并为以后增加工具、运行时等主题留下清晰结构。

## Goals / Non-Goals

**Goals:**

- 让用户从任何主要工作区都能发现并进入 Astra 文档中心。
- 默认展示一篇完整、与当前实现一致的“记忆”文档。
- 关闭文档中心时返回进入前的工作区，且不清空当前会话或未保存页面状态。
- 用独立组件和主题数据结构隔离文档内容，避免继续扩大 `App.tsx`。
- 支持窄屏、键盘导航、语义化文章结构和中英文界面。

**Non-Goals:**

- 本次不建设远程 CMS、全文搜索后端或公开文档站。
- 本次不改变记忆生产、召回、审计或 AutoDream 的运行逻辑。
- 本次不承诺除“记忆”外的其他文档主题内容。

## Decisions

### 1. 文档中心作为应用内顶层视图

把 `documentation` 加入现有 `view` 联合类型，并由侧边栏按钮进入。进入前记录当前非文档视图，关闭时恢复该视图。

相比外链 Markdown 或新浏览器窗口，这种方式可以保持桌面应用体验、离线可用并保留当前 React 状态；相比模态框，顶层视图能提供更好的长文阅读空间和移动端布局。

### 2. 文档内容由独立 React 组件承载

新增 `DocumentationCenter.tsx`，内部使用主题清单、语义化 `article`、锚点目录和可复用信息卡片。首个主题固定为 `memory`，未来可扩展主题清单，而不需要修改应用壳的导航协议。

本次不引入 Markdown 运行时或远程内容源，避免增加网络、解析和内容注入风险。静态内容可以随代码评审、测试和产品版本一起发布。

### 3. 用产品语言解释实现边界

记忆文章将明确区分：

- `MEMORY.md` 是提取规则和行为指导，不是记忆数据库；
- 运行时设置控制是否生产、是否召回及预算；
- 已保存记忆是可检索的结构化记录；
- AutoDream 是后台整理和版本演进，不直接等同于召回。

文章对“生效”拆为生产、激活、召回、注入四个时点，并单独展示 run/task/workspace/user 四级范围，避免把“已保存”误解为“每次回答都会使用”。

### 4. 复用 Astra 的本地化和视觉系统

组件通过现有 `useI18n()` 获取文案，并在 `styles.css` 中复用颜色、边框和间距变量。可见文字提供中英文翻译；文档结构使用原生标题、导航、表格和列表，确保屏幕阅读器与键盘可用。

## Risks / Trade-offs

- [静态文档可能随实现变化而过期] → 关键行为写入规格和内容回归测试；后续修改记忆逻辑时同步维护文档。
- [长篇翻译会扩大前端词典] → 首篇只覆盖记忆，使用完整句子作为稳定翻译键；未来主题仍放在独立组件中。
- [底部侧边栏项目增多可能挤压小屏] → 侧边栏已有滚动/折叠模式，文档入口采用与现有操作一致的紧凑样式，文档正文在窄屏变为单栏。
- [返回逻辑可能破坏当前视图] → 只切换顶层视图，不卸载应用状态源；记录进入文档前的视图，并为直接初始化提供聊天回退。

## Migration Plan

1. 发布前端组件、入口、样式、翻译和测试，不需要数据迁移。
2. 文档中心出现后默认从侧边栏进入“记忆”。
3. 如需回滚，移除 `documentation` 视图和入口即可，不影响后端或用户数据。

## Open Questions

- 后续是否将文档内容抽取为版本化 Markdown 或接入公开文档站，在首篇内容和信息架构经过使用验证后决定。
