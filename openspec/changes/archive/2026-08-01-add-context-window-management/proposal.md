## Why

Astra 当前不会向用户展示一次对话实际占用了多少模型上下文，也缺少在长对话逼近模型窗口时主动治理历史的机制。用户需要可观察的上下文状态、可靠的自动压缩，以及不依赖自动触发的手动 `/compact` 与 `/clear` 控制。

## What Changes

- 根据当前模型与提供商初始化上下文窗口容量，并在对话切换模型或新增消息后重新计算已用 Token、剩余 Token 和占用比例。
- 在聊天 Composer 中实时展示当前模型、上下文窗口总量、已用量和压缩状态，并对接近阈值的状态提供清晰提示。
- 在下一次模型调用可能超过安全预算前自动压缩较早的对话历史，保留近期消息、关键运行状态和一条可继续推理的结构化摘要。
- 建立可扩展的宿主侧 `/` 系统命令注册与执行机制，使系统预置命令与 Skill 搜索共用入口但保持不同语义。
- 首批预置 `/compact`，用于立即压缩当前对话上下文；预置 `/clear`，用于清除当前对话的模型上下文，同时保留可审计的对话记录。
- 系统命令仅在用户明确选择或提交完整命令时执行，不作为普通消息发送，也不创建模型 Run。
- 为上下文估算、模型窗口解析、自动/手动压缩、清除、命令交互和错误语义补充测试。
- 将供应商级的逗号分隔模型列表升级为模型级能力档案，由 Astra 根据供应商官方文档维护上下文窗口、最大输出和元数据来源；用户不能手动覆盖容量。
- 让聊天 Composer 与模型配置共享同一份有效上下文预算，并把模型选择器中的文字占位优化为紧凑、可访问的圆环使用率。

## Capabilities

### New Capabilities

- `conversation-context-management`: 定义模型上下文窗口初始化、Token 估算与实时状态、摘要压缩、自动阈值、手动压缩及上下文清除语义。
- `slash-system-commands`: 定义可扩展的系统预置 `/` 命令注册、发现、执行、错误处理，以及与 Skill 选择的共存规则。

### Modified Capabilities

- `agent-chat-ui`: 扩展聊天 Composer，使其展示实时上下文窗口信息，并在现有 Skill 斜杠面板中发现和执行系统命令。

## Impact

- 后端：对话/消息数据模型与仓储、模型配置解析、Prompt 历史组装、Run 创建前预算检查，以及新的上下文状态和命令 API。
- 前端：聊天状态加载、Composer 上下文指示器、统一斜杠选项、命令确认/执行反馈及国际化样式。
- 模型设置：在保留既有浏览器配置兼容的同时，只持久化模型标识；窗口、最大输出、官方资料来源和验证状态由服务端目录提供。
- 数据：需要持久化当前上下文代次、压缩摘要、截止消息和最近压缩元数据；既有对话默认从完整历史初始化。
- 兼容性：现有 Skill `skill_ids` 和消息提交协议保持兼容；历史消息不会因 `/compact` 或 `/clear` 被删除。
- 依赖：优先使用现有 provider usage 数据和本地确定性 Token 估算，不新增外部服务依赖。
