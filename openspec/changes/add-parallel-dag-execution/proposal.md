## Why

Astra 的可信计划已经能够表达 fan-out/fan-in DAG，调度器也能识别多个同时 ready 的节点，但当前 Run 仍只有一个 `active_node_id`，并按稳定顺序逐个执行，因此图谱展示的并行结构没有转化为实际吞吐和响应速度。现在需要把预留的多 ready-node 边界升级为受控并行执行，并让用户清楚看到哪些节点正在并行、等待什么资源以及如何在汇合点继续。

## What Changes

- 为 trusted Run 增加有界并行 DAG 调度：每个调度周期原子认领一批满足依赖、预算、能力和并发策略的 ready 节点，而不是固定选择 `ready[0]`。
- 将单一活动节点状态升级为版本化的活动节点集合和独立节点执行上下文，使多个节点可以并发推理、调用工具、产生证据并独立完成。
- 增加 Run、能力、工具提供方和副作用类别的并发限制；默认保持保守上限，并允许只读、无冲突分支优先并行。
- 增加工作区与外部副作用冲突检测：潜在写集合冲突、审批依赖或不可并发工具自动串行化，不以并行为由绕过权限、审批或沙箱策略。
- 定义并行节点的失败、取消、超时、重试、重规划和 fan-in 汇合语义；一个分支失败不得误取消无依赖关系的安全分支，汇合节点必须等待全部必要依赖达到允许状态。
- 对工具调用预算、token/turn 预算、审批 grant、状态版本和完成门实施原子记账，防止并发超额、重复消费、丢失更新或提前生成最终答案。
- 扩展图谱事件和快照，公开活动节点集合、并发槽位、节点执行身份、等待原因和批次/分支关联，同时保持事件有序、可重放和可由权威快照校正。
- 升级前端可信执行图谱：允许多个节点同时显示 running，突出并行分支、活动边、资源等待、汇合屏障和分支级失败；总体进度和当前执行摘要支持并发状态。
- 增加紧凑窗格和半屏工作台的并行状态可视化，避免用动画数量制造噪声，并继续支持键盘、屏幕阅读器、暗色、高对比和 reduced-motion。
- 增加确定性并发测试和真实耗时验证，证明独立分支产生时间重叠，同时保证有冲突或有依赖的节点仍严格串行。

## Capabilities

### New Capabilities

- `parallel-dag-execution`: 定义 trusted Plan 的有界并行调度、活动节点集合、节点执行隔离、冲突控制、失败传播、取消、汇合和确定性恢复。
- `parallel-dag-visualization`: 定义多个活动节点、并行分支、资源等待、汇合屏障和分支终态在可信执行图谱中的实时、响应式及无障碍呈现。

### Modified Capabilities

- `task-runner`: 将 trusted Run 从单活动节点执行升级为可恢复的多节点并行执行，并持久化并发状态和节点级执行关联。
- `general-agent-reasoning`: 将模型上下文和决策约束从唯一活动节点升级为隔离的节点工作单元，防止并行分支互相污染。
- `completion-gate`: 要求最终完成门等待所有必要分支和 fan-in 节点完成，并汇总并发分支证据。
- `low-latency-answer-streaming`: 支持并发节点增量的有界批处理、顺序约束和快照校正，避免事件风暴。

## Impact

- 后端：`PlanScheduler`、Agent Loop、Run/AgentState Schema、Plan/Run repositories、节点状态转换、工具执行、权限与审批、预算、取消、重规划、完成门和 SSE 事件。
- 前端：Plan 图谱快照与 reducer、`TrustedExecutionGraph`、节点/边状态、进度摘要、等待原因、历史恢复、国际化和可访问性。
- 数据与协议：从单一 `active_node_id` 迁移到活动执行集合；增加节点执行 attempt/worker 标识、调度批次、并发等待原因和资源声明，但不改变 Plan DAG 的不可变版本语义。
- 测试：调度器竞态、资源冲突、预算原子性、审批暂停、取消传播、分支失败、fan-in、重启恢复、SSE 乱序/重放，以及前端复杂多路并行图谱的单元、集成和浏览器验证。
- 性能与运维：新增可配置并发上限、运行中任务追踪、背压、超时和并发度指标；不引入分布式队列作为第一阶段前置条件。
