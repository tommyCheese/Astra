## Context

Astra 把同一 Task 的最近六个 Run 拼接成下一次 Run 的 `Conversation context`，但这一过程没有 Token 预算、模型窗口差异、压缩状态或用户控制。前端同时已经有 `/` Skill 搜索手势，系统命令若另建一套输入解析会产生焦点、键盘和普通文本语义冲突。

上下文治理必须满足两个约束：历史 Run 仍是审计和分享的事实记录；模型可见上下文可以独立压缩或清空。模型 API 不保证在请求前提供精确 Token 数，因此运行前需要确定性估算，调用后的 provider usage 只能用于计量校准而不能作为唯一保护。

## Goals / Non-Goals

**Goals:**

- 按 provider/model 初始化保守的上下文窗口，并以统一状态合同暴露容量、估算用量、比例、阈值和最近操作。
- 让 Run 创建与 Agent prompt 组装使用同一份对话上下文快照。
- 在安全阈值前自动压缩，并允许用户通过 `/compact` 或 `/clear` 立即改变模型可见上下文。
- 保留完整历史、运行审计和分享内容。
- 建立可扩展但当前只注册两个命令的系统命令目录。

**Non-Goals:**

- 不删除历史 Run、工具记录、工件或分享快照。
- 不承诺本地估算与任一 provider tokenizer 逐 Token 完全一致。
- 不允许用户通过任意 `/` 文本调用服务器函数；只执行注册表中的预置命令。
- 不在本次加入自定义命令、参数化命令、命令插件或命令权限 DSL。
- 不压缩单个仍在执行的 Run 内部 Agent turn；本次治理 Run 之间的对话历史。

## Decisions

### 1. 在 Task 上持久化独立的 `context_state`

为 `tasks` 增加 JSON `context_state`，保存 schema version、摘要、已折叠 Run IDs、最近动作和时间。Run 与消息记录不修改、不删除；模型上下文由“摘要 + 未折叠的已完成 Run + 当前请求”投影生成。

`/clear` 把当前已有 Run 全部加入折叠集合并移除摘要，因此后续模型看不到清除前内容。`/compact` 保留最近若干 Run，把更早的可见 Run 与已有摘要合并为有界结构化摘要。重复命令幂等且不会影响新命令之后创建的 Run。

替代方案是删除历史或修改旧 Run 内容，会破坏审计与分享；为每条消息增加 generation 列更规范但迁移面更大，当前 JSON 状态足以表达投影。

### 2. 使用保守模型窗口目录与确定性 Token 估算

服务端维护按 provider 和模型 family 匹配的窗口目录；已知 family 使用预置容量，未知模型回退到保守的 128K。窗口解析是纯函数，前后端不各自维护不同表。

Token 估算按 Unicode 文本类别计算：CJK 等宽字符近似单 Token，拉丁与其他文本按字符分段估算，并加入每条消息固定开销。状态明确标记 `estimated=true`。计算包含摘要、可见历史、当前草稿估算和固定系统/工具保留量；百分比以可用输入预算为分母。

替代方案是引入各 provider tokenizer，会显著增加依赖、模型版本耦合和前端负担。provider 返回的 usage 发生在调用后，不能保护本次请求。

### 3. 自动压缩在 Run 创建事务内、首次模型调用前执行

创建已有对话的 Run 时，服务先用所选模型和新 goal 计算 projected usage。达到自动阈值时，在同一数据库事务内执行压缩、重新计算，再创建 Run；因此成功创建的 Run 必定冻结在压缩后的上下文上。若单个当前请求仍超预算，则返回分类错误，不启动模型。

自动压缩保留最近四个已完成 Run；摘要采用确定性、有长度上限的提取式格式，记录用户目标和最终回答要点。这样无需额外模型调用、API Key 或隐性成本，也不会因摘要模型失败阻断主请求。

替代方案是后台压缩，存在下一个请求已经越界而压缩尚未完成的竞态；用模型生成摘要质量更高，但引入额外调用、延迟和失败路径，后续可在相同服务接口内替换。

### 4. 状态与命令通过后端 API 暴露

新增上下文状态读取 API，接收当前 provider/model 和可选 draft 文本，返回窗口与投影指标。新增系统命令目录 API，返回稳定的 name、description、effect 和 availability；执行 API 只接受目录注册的名称，并将 `/compact`、`/clear` 分派给 Context Manager。

前端在对话/模型/草稿变化时请求状态，并对草稿输入做短延迟刷新。命令执行成功后重新加载对话和状态；命令文本不进入消息、不创建 Run。

上下文指标归属于模型选择器：模型名旁显示紧凑的 `used / window` 或最近压缩动作，并用同一控件的进度色、tooltip 与可访问名称暴露状态和剩余量。Composer 不为上下文增加独立行，避免持续挤占输入空间。

替代方案是把命令硬编码为前端按钮，会让其它客户端无法发现或复用，且无法形成可扩展系统命令合同。

### 5. Skill 与系统命令共享检测器和列表框

现有命令边界、IME、URL/路径排除逻辑继续作为唯一 slash token 检测器。统一 option 类型包含 `kind=command|skill`；系统命令优先显示，Skill 继续形成一次性 token。选择 Skill 时删除查询并加入 `skill_ids`；选择系统命令时删除查询并立即调用命令 API。

完整且唯一匹配的 `/compact` 或 `/clear` 在 Enter 时执行；未知 `/text` 仍是普通消息。执行期间禁用重复命令并提供可访问状态，失败时保留命令文本以便重试。

### 6. 使用模型级能力档案解析有效上下文预算

供应商配置把每个模型表示为稳定的模型档案，而不是只保存一个逗号分隔 ID。模型档案只保存模型标识；provider 公布的总窗口或输入上限、最大输出、官方资料 URL 和验证状态来自服务端维护的版本化能力目录。既有 `models: string` 或含手动容量字段的浏览器配置在加载时迁移为只含模型标识的 `models: ModelProfile[]`，保存后不再写入容量。

上下文状态、命令和 Run API 只接收 provider/model 身份，不接收客户端窗口覆盖或最大输出。服务端目录是唯一预算来源；已知模型使用官方预置值，未知模型使用保守 fallback，并把官方资料 URL、来源和是否已验证返回给客户端。客户端不能通过查询参数或 Run payload 放大或缩小预算。

支持 Models API 的 provider adapter 可逐步接入自动同步，但运行时不把外部网络读取作为聊天可用性的前置条件；目录更新经过代码评审和测试后随 Astra 发布。本地或兼容端点无法从官方模型身份确认容量时使用保守 fallback。

### 7. 用模型选择器内的圆环表达实时上下文占用

模型选择器保留模型名和策略摘要，把原本占据整行的 `used / window` 文字替换为右侧圆环。圆环使用 SVG stroke 展示占用比例，中心不塞入难以阅读的数字；精确 `used / window`、剩余量、来源和最近上下文动作通过 tooltip、菜单详情和可访问名称提供。

视觉 tooltip 只由圆环自身的指针悬浮触发，悬浮模型名称、策略摘要或选择器空白区域不会弹出；选择器继续通过 `aria-describedby` 暴露完整上下文描述，避免依赖 hover 才能获取状态。

模型、会话、草稿或模型配置变化时，前端取消过期状态请求并用同一模型档案刷新。切换到更小窗口后，状态立即进入 warning/critical；Run 创建仍由服务端执行自动压缩或容量拒绝，避免 UI 与实际调用预算分叉。

## Risks / Trade-offs

- [估算低于 provider 实际 Token] → 使用保守算法、系统保留量和 80% 自动阈值，并在状态中明确估算属性。
- [提取式摘要遗漏细节] → 保留最近 Run、限制只折叠较早历史，并保留完整审计记录供用户查看。
- [JSON 中 folded IDs 随对话增长] → 每次 compact 去重；当前规模远小于 Run 本体，后续可迁移为 generation 列。
- [压缩与并发创建 Run 竞态] → 在同一会话事务中刷新 Task 状态并使重复折叠幂等；活动 Run 存在时命令返回状态错误。
- [用户误触 `/clear`] → clear 只影响模型投影、不删除记录，UI 明示“保留历史”效果。
- [不同模型切换导致占用比例跳变] → 状态总是携带解析后的 provider/model/window，模型切换立即重新计算。
- [官方模型容量发生变化] → 目录条目保存官方资料 URL并通过版本化代码更新；未知或尚未更新的模型使用保守 fallback。
- [圆环仅用颜色表达状态] → 提供独立可访问名称、tooltip、状态文本和模型菜单内的精确数字。

## Migration Plan

1. 增加 nullable/default-safe 的 `tasks.context_state` JSON 列；既有行按空状态解释为完整历史。
2. 部署 Context Manager、窗口目录、状态/命令 API 和 Run 创建前自动压缩。
3. 将 Engine 历史拼装切换为 Context Manager 的投影，并保留旧的最近 Run 上限作为最终保护。
4. 部署统一 slash UI 和上下文指标；旧客户端仍可继续创建 Run。
5. 回滚时停止读取 `context_state` 即恢复旧的最近历史行为，列可保留，不需要恢复数据。
