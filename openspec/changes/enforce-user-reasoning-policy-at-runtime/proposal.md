## Why

Astra 已能接收并保存用户选择的推理强度、规划策略和反思策略，但 Agent Loop 仍主要读取全局默认值，反思也会绕过用户开关直接触发。这会让界面设置与实际行为不一致，因此需要把有效策略快照真正接入运行时控制。

## What Changes

- 让用户选择的推理强度预算实际控制最大 Agent 轮次、工具调用数和反思次数。
- 让直接、自适应、先规划三种规划策略产生可观察且可测试的不同运行路径。
- 所有自动反思统一经过反思门控，严格遵守关闭、失败时、按需和每轮触发方式。
- 仍允许安全规则对高风险任务提高最低规划、批准和验证要求；除此之外以用户选择为优先。
- 增加运行时行为测试，不再只验证策略是否被传递和保存。

## Capabilities

### New Capabilities

- `runtime-reasoning-policy-enforcement`: 定义用户推理、规划和反思选择如何在 Agent Loop 中实际控制预算、路径和触发行为。

## Impact

- 修改后端 `RunEngine`、`AgentLoop` 与策略门控的连接方式。
- 不改变现有 Run 创建 API 字段，但会改变这些字段对应的实际运行行为。
- 增加策略组合、预算边界和反思触发的后端测试。
- 不增加新的外部依赖和工具权限。
