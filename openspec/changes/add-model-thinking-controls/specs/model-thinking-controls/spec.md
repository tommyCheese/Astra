## ADDED Requirements

### Requirement: 系统声明模型级思考能力

系统 SHALL 根据 Provider 和模型标识返回模型思考能力，能力 MUST 包含是否支持思考、开关类型、可选深度、默认状态、默认深度、能力版本以及不可用或受限原因。

#### Scenario: 模型支持可选思考
- **WHEN** 客户端查询一个支持混合思考的已知模型
- **THEN** 系统返回可切换的思考开关及该模型支持的有序深度集合
- **THEN** 系统返回有效的默认开关和默认深度

#### Scenario: 模型强制思考
- **WHEN** 客户端查询一个仅支持思考模式的模型
- **THEN** 系统声明思考始终开启且开关不可关闭
- **THEN** 系统仅返回该模型实际支持的深度选项

#### Scenario: 未知或不支持的模型
- **WHEN** Provider 与模型组合没有已声明的思考控制能力
- **THEN** 系统返回不可用状态和稳定的原因代码
- **THEN** 系统 MUST NOT 声明未经确认的 Provider 参数

### Requirement: 运行接受规范化的模型思考选择

系统 SHALL 在模型运行配置中接受可选的思考开关、能力声明中的深度 ID 和能力版本，并 MUST 拒绝任意 Provider 原生推理参数透传。

#### Scenario: 提交受支持的显式选择
- **WHEN** 用户为当前模型提交受支持的开关状态和深度
- **THEN** 系统将其规范化为该 Run 的不可变有效模型思考配置
- **THEN** 系统将有效配置映射为当前 Provider 所需的请求参数

#### Scenario: 提交过期深度
- **WHEN** 用户提交的深度不再包含在当前模型能力中
- **THEN** 系统回退到该模型的默认深度
- **THEN** Run 快照记录请求值、有效值和调整原因

#### Scenario: 尝试关闭强制思考模型
- **WHEN** 用户为 `always_on` 模型提交关闭思考
- **THEN** 系统将有效状态规范化为开启
- **THEN** Run 快照记录模型不允许关闭的原因

### Requirement: 模型思考选择按模型隔离

客户端 SHALL 以 Provider 与模型组成的稳定键分别记忆下一次运行的用户思考选择，并 SHALL 在能力变化时只恢复仍然有效的值。回答模式 MUST NOT 产生另一套思考偏好或自动修改已保存选择。

#### Scenario: 在两个模型之间切换
- **WHEN** 用户为两个模型分别选择不同的思考状态或深度并来回切换
- **THEN** 客户端为每个模型恢复各自最近一次有效选择

#### Scenario: 同一模型在两种回答模式间切换
- **WHEN** 用户为一个模型选择思考深度后在快速模式和可信模式之间切换
- **THEN** 客户端保留该模型的同一份用户选择
- **THEN** 回答模式不会自动抬高、降低或关闭模型思考

#### Scenario: 已保存选项不再受支持
- **WHEN** 客户端加载的已保存深度不在最新能力声明中
- **THEN** 客户端改用该模型的默认深度
- **THEN** 客户端 MUST NOT 向运行请求发送过期深度

### Requirement: 实际模型思考配置可审计

系统 SHALL 在 Run 模型策略快照中记录模型思考配置的请求值、有效值、来源、适配器和调整原因，并 SHALL 在模型调用 usage metadata 中记录实际应用结果。系统 MUST NOT 保存隐藏思考正文、凭据或完整提示。

#### Scenario: 新客户端显式配置思考
- **WHEN** Run 携带显式模型思考配置
- **THEN** Run 快照将来源记录为显式模型控制
- **THEN** 每次模型调用记录最终应用的非敏感参数摘要

#### Scenario: 模型能力导致降级
- **WHEN** 请求的思考配置不能被当前 Provider 或模型应用
- **THEN** Run 快照和调用 metadata 记录降级原因
- **THEN** 基础模型请求在安全省略不支持字段后继续执行

### Requirement: 未携带模型思考配置的客户端保持兼容

系统 SHALL 在运行请求未携带显式模型思考配置时继续使用现有 Agent 推理强度到模型参数的兼容映射。

#### Scenario: 旧客户端创建运行
- **WHEN** 请求只包含 `reasoning_policy.reasoning_effort` 而不包含 `model.thinking`
- **THEN** 系统按照现有推理强度映射模型调用参数
- **THEN** Run 快照将来源记录为旧推理策略兼容路径

### Requirement: 回答模式不分配模型思考预算

系统 SHALL 将模型思考开关与深度作为独立的用户选择，并 MUST NOT 根据快速或可信回答模式决定默认值、限制深度集合、自动升降选择或分配模型思考预算。没有已保存选择时，客户端 SHALL 使用模型能力声明的中性默认值并允许用户直接修改；相同深度 ID 在两种回答模式中 MUST 映射为相同的模型行为。

#### Scenario: 用户首次选择支持思考的模型
- **WHEN** 当前模型没有已保存的用户思考选择
- **THEN** 客户端显示模型能力声明的中性默认值和全部受支持选项
- **THEN** 进入快速或可信模式不会改变该默认值
- **THEN** 用户可以直接选择开关状态和深度

#### Scenario: 用户在快速模式显式选择高深度
- **WHEN** 用户在快速模式选择当前模型支持的高思考深度
- **THEN** 系统使用高深度模型参数
- **THEN** 运行仍保持快速模式的编排与验证行为

#### Scenario: 用户在可信模式关闭思考
- **WHEN** 用户为支持关闭的模型在可信模式显式关闭思考
- **THEN** 系统关闭该模型的扩展思考参数
- **THEN** 可信模式的计划、审批、安全门和验证要求保持不变

#### Scenario: 切换回答模式
- **WHEN** 用户在已经选择模型思考深度后切换回答模式
- **THEN** 客户端和运行时保持该用户选择
- **THEN** 模式切换只改变对应的编排与保障行为
