## Why

当前聊天界面在 Agent 完成首轮决策前只显示等待动画，已有的思考过程又默认折叠并依赖完整 RunView 刷新，用户往往要等到回答出现后才能理解 Astra 正在做什么。需要把可审计的推理摘要、运行阶段、工具活动、反思和验证过程实时呈现在对话中，让长任务从提交开始就持续提供可感知反馈。

## What Changes

- 在运行创建后立即建立实时过程视图，并在规划、决策、工具执行、反思、验证和回答组织阶段持续更新。
- 扩展 SSE 过程事件协议，支持可恢复的阶段事件与经过短时间窗合并的可审计推理摘要增量。
- 前端使用本地过程状态归约器直接消费 SSE，而不是为每个过程事件重新加载完整 RunView。
- 思考过程在运行期间默认展开、允许用户主动收起；回答稳定后保留为可展开的审计记录。
- 明确只展示安全、简洁、可审计的推理摘要，不请求、不依赖也不暴露隐藏 Chain-of-Thought。
- 将本 change 作为本轮大型聊天体验优化的统一范围，后续同一阶段的过程展示、回答衔接和聊天交互改进在归档前继续补充到本 change。

## Capabilities

### New Capabilities

- `live-agent-process-streaming`: 定义运行阶段、推理摘要、工具、反思与验证过程的实时 SSE 协议、恢复语义和安全边界。

### Modified Capabilities

- `agent-chat-ui`: 将思考过程从终态折叠审计面板扩展为运行期间实时、默认可见且可交互的聊天内容。
- `low-latency-answer-streaming`: 将现有低延迟流式机制扩展到过程事件，并约束过程增量的刷新与渲染开销。

## Impact

- 后端：`RunEngine`、`AgentLoop`、`ModelClient`、Run 事件持久化和 SSE API。
- 前端：SSE 客户端、聊天状态管理、`ProcessPanel`、过程时间线样式与无障碍状态播报。
- 协议：新增向后兼容的过程事件类型；现有客户端可忽略未知事件。
- 数据：复用现有 RunEvent 与 AgentTurn 存储，不新增数据库表。
- 安全：不传输模型供应商隐藏推理内容，不在过程事件中暴露凭据、内部路径或未清洗工具输入。
